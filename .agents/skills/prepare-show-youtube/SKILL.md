# Prepare a show for YouTube

Work from the project root. Collect the show date, original recording path, show start, wrap-up and video-stop timecodes, and ordered named segment starts. For a single recording, segment times refer to the original source; for joined recordings, map the supplied source timecodes onto the joined timeline as described below. Accept MM:SS or HH:MM:SS with fractional seconds. Ask for missing inputs and clarify ambiguous dates or segment labels. By default the first and last **listed segments** receive chapters but no game-title overlays; use an explicit `titled: true` on a game at either edge. Show `improv-circus.com` as the current title during the opening (until the first game) and closing (from the explicit wrap-up marker through video stop). Keep the website on one line, reducing its font size to fit without splitting the domain. Never show the website between games. Distinguish “wrap up” (games end and outro begins) from “stop video” (actual trim boundary). Ask what an ambiguous “show end” means; never assume it means stop video. Store these as `wrapUp` and `stopVideo`, using the same timeline as segment timecodes. `end` remains a legacy alias for `stopVideo`; reject conflicting values. These markers do not automatically add chapters. Do not infer game names or timing from show data.

## Resolve and prepare

Use `scripts/prepare.mjs` from this skill. It reads project YAML with merge support and mirrors the show's nullish overrides, local-date matching and slug convention. It resolves theater, regular players and guests. Do not apply the separate promo skill's no-year rule: recordings include the full show date. For a no-match or multiple-match date, resolve the date or supply an explicit matching `showSlug` before proceeding.

Create a unique temporary working directory inside the project’s local `tmp/` folder for tests, previews and rendering intermediates. Save the specification there; relative paths resolve beside it. Always set `tempDirectory` to that directory. Keep previews, candidate stills, specifications, logs and all intermediate files temporary.

Use `videos/<show-slug-with-date>/` for the show’s originals and final deliverables, deriving the slug from resolved show data and appending the show date when not already present. The helper derives this directory beside the first real source (following temporary source symlinks), or reuses it when originals are already inside it. `outputDirectory` optionally specifies the destination relative to the specification. Before a new render, run `--mode organize`: it moves and renames the originals, moves recognized existing final video/description and named review MP4s, repairs supplied temporary source links, and updates specification paths. Single-source naming is `<slug>-original.<ext>`; multiple sources use `<slug>-original-1.<ext>`, `-original-2.<ext>`, etc., in specification order. Preserve extensions and contents. It checks all destination collisions first, never overwrites originals, and verifies relocation checksums. Filesystem escalation may be required for the videos directory.

Never relocate inputs while an existing render or its verification/publication is running. For an existing detached job, run `node .agents/skills/prepare-show-youtube/scripts/organize-after-job.mjs --job /path/to/job --spec /path/to/recording.json --root /path/to/project` in a durable background process. It waits for successful `full-render-status.json` completion before organizing; failures leave originals in place. Its separate `organization-status.json` and redirected log remain in the temporary job directory. Do not restart the render.

A minimal single-source specification:

```json
{
  "date": "2026-09-19",
  "source": "source.mp4",
  "start": "02:10",
  "wrapUp": "1:15:00",
  "stopVideo": "1:18:00",
  "segments": [
    {"time":"02:10","name":"Opening"},
    {"time":"05:30","name":"New Choice","titled":true}
  ]
}
```

Apply a crossfade only when the user supplies two or more input videos; never apply it to a single-video recording. For split recordings, keep `source` as the primary recording and add `sources: [{"source":"part1.mp4","start":"05:08","end":"06:41"},{"source":"part2.mp4","start":"00:00","end":"1:09:42.015"}]` and `crossfade: 0.2`. Use a quick 0.2-second crossfade (six frames at 30 fps); keep it at or below 0.25 seconds unless the user requests otherwise. The helper trims and joins these intervals with video and audio crossfades in the same render, preserving the originals. Joined recordings use 30 fps. Set specification `start` to `00:00`, `stopVideo` to the sum of retained durations minus overlaps, and map `wrapUp` and segments onto that joined timeline. Keep original source timecodes in the sidecar for traceability. Keep the specification, previews, staging files and intermediate media in the local temporary directory. Publish final media and the YouTube description inside the show directory. Obtain filesystem escalation when those final destinations are outside permitted write roots.

Relative source and optional `showLogo`, `brandLogo`, `layout` paths resolve beside this specification. Optional `showSlug` disambiguates dates. Supply optional `summary` with a concise factual retrospective description based on the resolved show description; otherwise the helper uses the show headline. Avoid carrying ticket offers or future-tense invitations into recording copy. Default Wry vs. Dry and Improv Circus logos come from `marketing/Assets/00_brand_logos/`. For other shows supply the appropriate approved show logo; do not substitute Wry vs. Dry. Inspect the chosen assets. A broken marketing symlink or missing assets must be resolved rather than replaced with invented marks.

Run:

```bash
node .agents/skills/prepare-show-youtube/scripts/prepare.mjs --spec /path/recording.json --mode validate
node .agents/skills/prepare-show-youtube/scripts/prepare.mjs --spec /path/recording.json --mode organize
node .agents/skills/prepare-show-youtube/scripts/prepare.mjs --spec /path/recording.json --mode preview
node .agents/skills/prepare-show-youtube/scripts/prepare.mjs --spec /path/recording.json --mode render
```

The helper requires Node with project dependencies, FFmpeg/FFprobe and ImageMagick `convert`/`identify` (`montage` for highlight contact sheets). `--root /path/to/project` supports running elsewhere. Validation performs no media rendering. For a user-requested preview length, set `previewDuration` to seconds (for example, `120` for two minutes). This previews from the trimmed show-start offset, not the original file start or a window centered on the transition. Do not move the start or change the requested duration; flag if the transition lies outside it. Preserve the full-show title timing in excerpts. Without `previewDuration`, preview checks the first interior-title entrance and exit. Preview writes a branded still, an animated first interior-title entrance/exit excerpt, and the draft description in `improv-circus-<slug>-preview` inside `tempDirectory` (set `tempDirectory` inside the project’s local `tmp/` folder). Use faster encoding only for explicitly identified review copies; full renders always use H.264 medium with an 8 Mbps video target and AAC at 192 kbps. Copy only user-requested, clearly named review MP4s into the show directory; specifications, stills, logs and intermediate files stay temporary. Inspect previews before the full render; no separate approval checkpoint is required unless the user requests one; honor requested preview approval before a full render. Fix layout issues via a specification-local layout JSON derived from `assets/layout.json`.


## User-supplied source repairs

Only apply a repair when requested. Store `sourceOverlays: [{"sourceIndex":0,"sourceStart":"05:47.82","image":"patch.png","x":615.12,"y":67.38,"width":722.29,"height":406.48,"crop":{"left":3.7559,"top":3.1921,"right":5.7566,"bottom":6.3003}}]`. `sourceIndex` is zero-based; `sourceStart` is an original-source timestamp. Clarify whether user times are source-relative or relative to the trimmed show, and whether placement describes the image before or after cropping. The helper interprets the placement as the full image before cropping: resize it to the supplied rectangle, crop inward by the percentage of each edge, and retain the cropped image’s inset position and scale. Round fractional geometry to the nearest output pixel. Coordinates use the normalized 1920×1080 frame. Composite onto the specified source before source crossfades, so the repair leaves with that source. Validate geometry and timing and retain supplied values in the show specification. If a time-limited positioning/timing review is requested, produce that preview and wait for approval before full rendering.

## Promotional stills

Produce five suggested promotional stills per game, plus a labeled contact sheet per game, as a separate operation using the original recordings. This does not require rendering or rerendering the full video. Read [references/highlights.md](references/highlights.md) for candidate sampling, visual selection and export commands. Keep candidate frames and selection records temporary; publish only selected source-resolution JPEGs and contact sheets inside the show directory. They must be clean, uncropped images without added video branding. Opening/closing selections are optional. If fewer than five usable distinct moments exist, deliver fewer and explain why rather than padding with duplicates.

## Text progress

Run the helper attached to a visible terminal for live output. It prints a plain-text line every 20 seconds during rendering and full-decode verification: `Rendering 42.0% | ETA 1:10:00`. Percent uses processed media time divided by the stage duration; ETA uses FFmpeg's reported processing speed and is approximate. Each stage has its own percentage; rendering completion does not mean verification or final publication is complete. Startup shows `ETA calculating`, and failures retain FFmpeg diagnostics and a nonzero exit code. No dashboard or local server is needed.

For an already detached job using `full-render.log` and `full-render-status.json` (with `stage` and `duration_seconds`), use `python3 .agents/skills/prepare-show-youtube/scripts/watch-progress.py /path/to/job-directory` in a visible terminal. This prints every 20 seconds from the latest logged FFmpeg measurement; `--once` checks a single snapshot. It reports stale measurements and stops on complete/failed status. Ctrl+C stops only this monitor. Do not restart a render solely to add progress visibility. Detached output redirected to a log will not appear automatically in the CLI; give the user the monitor command. Keep logs and status files in the temporary working directory.

## Visual and audio treatment

`assets/branding-reference.jpg` is the reusable composition reference, not a source of show facts. Use the compact default footer: logos at half the original reference size (160×120 show-logo box and 160×83 brand-logo box), occupying the bottom 120 pixels above the existing lower margin. Keep title and theater font sizes unchanged; use a slightly smaller 28-pixel date below the 34-pixel theater name, with a thin 0.5-pixel 50% gray (`#808080`) outline; reduce transparent vertical padding and use the horizontal space freed by smaller logos. The optional `websiteTitle` layout overrides preserve the website’s fitted size when widening the game-title area. Layout: show logo lower left, Improv Circus lower right, title between the left logo and theater/date, right-aligned theater name in bold white and full date in gray. Branding and venue/date persist throughout; no extra footer band. Logos retain proportions and transparent edges. The bundled Luckiest Guy font and Apache license come from https://github.com/google/fonts/tree/main/apache/luckiestguy. Title fill is screenshot-matched deep yellow (`#f3ed1d`), with a thin 2-pixel black outline and a 5-pixel drop shadow. Use `assets/long-title-reference.jpg` for long-title treatment: “Audience Sound Effects” wraps naturally as “Audience Sound” / “Effects.” Prefer readable two-line text over shrinking everything onto one line. The title area extends upward to accommodate two lines while keeping its lower edge near the logos. Wrap at word boundaries and reduce font size only as needed to fit the full title, outline and shadow inside its bounds. Do not truncate names or overlap branding or venue/date; stop if the minimum font size cannot fit legibly.

Interior titles wipe in left to right over 0.5 seconds at segment start. The exit begins five seconds before segment end and wipes right to left over 0.5 seconds. The next segment start defines the end; explicit wrap-up closes the final game-title interval while video stop retains the outro. Validate wrap-up within the trimmed recording and after all game starts. Legacy specifications without wrap-up keep their prior behavior. Interior segments shorter than six seconds require corrected timing. The complete text, outline and shadow are clipped together; this is a wipe, not a slide or fade.

Output is accurately trimmed, proportionally scaled/padded black to 1920×1080, square pixels, source frame rate, H.264 medium/yuv420p with an 8 Mbps video target (`-b:v 8M -maxrate 8M -bufsize 16M`), AAC at 192 kbps (`-c:a aac -b:a 192k`), fast-start MP4. Use these same bitrate settings for normal previews and full renders; do not use CRF or silently change bitrates. The video bitrate is a constrained average target, so simple scenes may encode below it; AAC bitrate is also an encoder target. Metadata-only and audio-only stream-copy operations retain the existing video bitrate. Apply `dynaudnorm=f=25:g=11:p=0.9,volume=3.0,alimiter=limit=0.95` to audio. FFmpeg requires an odd Gaussian window; `g=11` is the effective value of the supplied `g=10` example, without its warning. Video cannot be stream-copied with these transformations. Preserve the recording and do not edit project show data.

## Opening music

Replace the opening show audio with `marketing/Assets/20_audio/Power On (Instrumental).mp4` from the beginning of the track. Ask for the original-source timestamp where the crossfade back to show audio must be complete; never guess it or interpret it as a trimmed-output timestamp. Store `introAudio: {"source":"/absolute/path/to/Power On (Instrumental).mp4","fadeComplete":"05:19"}` in the specification. For split recordings this timestamp refers to the first source. Map it using the retained source start (05:19 minus 05:08 gives 11 seconds in the output). Reject fades outside the retained opening source or shorter than 0.5 seconds after show start, and reject music too short to cover the intro. Leave `introAudio` absent only when no opening override is requested; when configuring it, prompt for missing timing.

Mute show audio until 0.5 seconds before fade completion, then linearly fade the music out and the synchronized show audio in over 0.5 seconds. Keep show audio at its existing normalized level afterward. Previews use the same full-show timing and music offset. Music is peak-limited before mixing; the linear crossfade avoids summing both sources at full volume.

For an already rendered video, use `node .agents/skills/prepare-show-youtube/scripts/apply-intro-audio.mjs --source /path/video.mp4 --music /path/music.mp4 --fade-complete 00:11 --output /project/tmp/video-intro-audio-review.mp4`. This command's timestamp is explicitly relative to the finished video. It copies video with `-c:v copy`, encodes AAC 192 kbps, preserves metadata/chapters and fast-start layout, and does not normalize the rendered show audio again. Never overwrite the input. Leave a requested review copy under local `tmp/` until the user reviews or moves it; it is not a disposable test fixture. Verify the output and clean up intermediate media.

## Description and verification

Use only standard MP4 metadata: `title`, `description`, `date`, `artist` and `comment`. Put the full timestamped description in `description`, and the show date, theater name, street address and performers in `comment`. Do not add custom/extended fields or a second metadata system without user confirmation. Use `date` for the known show date; do not invent an exact recording time. Write the standard MP4/iTunes ItemList layout with `-movflags +faststart`, omitting `use_metadata_tags` (which switches to mdta and can hide the fields from Windows Explorer). For metadata-only changes use `-c copy` to preserve both audio and video. Verify with FFprobe and, when Windows is available, its property reader for `System.Title` and `System.Comment`; FFprobe alone does not establish Explorer compatibility. Use project theater data and omit unavailable address fields rather than guessing. Keep review copies in local `tmp/` when requested. An intentionally unspecified subtitle, rating or keyword list may remain blank.

The helper generates `improv-circus-<show-slug-with-date>-youtube-description.txt` beside the matching MP4. Review the copy for readable factual wording: resolved show identity, date, theater, regular/guest names, summary, website and show-page links. Adapt promotional present/future-tense wording to describe a recording without inventing events or claims. Chapters include every supplied segment with show start subtracted; add `0:00 Show start` when needed. Wrap-up and stop-video markers do not automatically become chapters. Flag fewer than three chapters, chapters shorter than ten seconds, or timestamps that collapse to the same whole second; do not alter supplied timing to claim YouTube eligibility.

The helper checks source streams, timestamps, dependencies and assets before rendering, and probes/decodes the completed MP4 before publishing its local filename. Listen to a sample for intelligibility, normalization pumping/clipping and sync; inspect the start/end, both wipe boundaries, long labels, letterboxing and logo fidelity. Automated checks do not guarantee perceptual quality. If no real recording was supplied, validate the skill with a synthetic fixture and report that limitation.

Existing outputs are never replaced implicitly. Use `--replace` only after the user explicitly authorizes replacement for those destinations. Filesystem escalation is still required outside permitted write roots; a marketing symlink does not expand permissions. Return output links and verification results. Leave everything local and uncommitted unless separately instructed.
